# Docs platform quirks

Read when D (CHECK) reaches the platform build, or when a platform behaves unexpectedly.
Add generic findings here; project-specific ones go to the adapter.

## Hosted editor with two-way git sync (GitBook-style)

- **Humans and agents commit to the same branch.** The editor lands commits
  continuously; a local checkout is usually stale. Always `git pull --ff-only` first and
  check `git status` for leftovers that would overwrite newer editor work.
- **No build gate.** Broken links and unlisted pages are accepted silently. A page
  missing from the nav file (`SUMMARY.md`) is invisible — `docs-check.py nav` is the only
  warning.
- **The nav label can become the page title and URL slug.** The editor may overwrite the
  page's H1 to match the nav label on write-back; choose the label you want as the title.
- **Write-backs renormalize the whole space**: emphasis markers, bullet characters, image
  locations (moved into an assets directory), auto-created stub pages for missing nav
  targets. Expect large diffs from tiny edits; never review a write-back expecting a
  small diff.
- **Front matter**: only the keys the platform documents are honoured; do not hand-write
  platform-managed keys (visibility, indexing).
- **Callouts** use the platform's own block syntax (a few fixed styles); MkDocs-style
  `!!!` admonitions left over from a migration render as literal text — grep for
  `^\s*(!!!|\?\?\?)` after migrating.
- Agent commits are distinguishable from human ones only by a commit trailer (e.g.
  `Co-Authored-By:`) when the sync uses a shared token — keep the trailer on every agent
  commit.

## MkDocs (Material)

- `mkdocs build --strict` turns warnings (broken links, pages not in `nav:`) into errors
  — the strongest gate of the common platforms; run it before committing.
- If the docs build runs inside a deploy image build, a docs typo can block the deploy of
  everything else — keep the docs build in its own job.
- Pages not in `nav:` are still built and reachable by URL, but not navigable.

## Docusaurus

- `npm run build` fails on broken internal links by default (`onBrokenLinks: 'throw'`);
  keep it that way.
- Sidebars may be autogenerated from the directory tree — a stray file becomes a page.
- Versioned docs: edit the current version, not the frozen copies, unless back-porting.

## Sphinx

- `sphinx-build -W --keep-going` makes warnings fatal; orphan pages warn unless marked
  `:orphan:`.
- API pages from autodoc are generated — fix docstrings, not the output.

## Generated API references (OpenAPI, typedoc, …)

- Never hand-edit the output. Fix the source annotations, regenerate, and review the
  diff of the generated file.
